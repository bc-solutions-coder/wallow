# wallow-auth — Wallow's authentication frontend

`@bc-solutions-coder/wallow-auth` is the app that renders every screen a user
sees while signing in: login (password, OTP, magic link, external providers),
registration, email verification, invitation acceptance, MFA challenge and
enrolment, consent, forgot/reset password, logout, and the terms, privacy,
access-request and error pages that hang off them.

It is a **TanStack Start** (React 19) app, and — unlike `wallow-web` — it is a
**pure same-origin reverse proxy, not a BFF**. It holds no session, no cookie jar
and no OIDC client. `/v1/**`, `/connect/**` and `/.well-known/**` are forwarded
verbatim to the Wallow API, `Set-Cookie` headers included, so the browser talks to
a single origin for the whole OpenIddict handshake while the API remains the thing
that actually issues the cookies.

> This app is not published. It is exercised by its own Playwright suite
> (`e2e/`, see [E2E](#e2e)) and by `wallow-web`'s cross-app login journey via
> `docker/docker-compose.test.yml`.

## Commands

Run from the repo root, or with `--filter @bc-solutions-coder/wallow-auth`. No
package build is needed first — in-repo every `@bc-solutions-coder/*` exports map
resolves to that package's `src/`, and `dist/` is applied at publish time.

```bash
pnpm --filter @bc-solutions-coder/wallow-auth dev        # vite dev on http://localhost:3002
pnpm --filter @bc-solutions-coder/wallow-auth build      # vite build -> .output/server + .output/public
pnpm --filter @bc-solutions-coder/wallow-auth start      # node .output/server/index.mjs
pnpm --filter @bc-solutions-coder/wallow-auth typecheck  # tsc --noEmit
pnpm --filter @bc-solutions-coder/wallow-auth test       # vitest run  (test:watch for watch mode)
pnpm --filter ./apps/wallow-auth test:e2e                # playwright test
```

Every vite/vitest script passes `--configLoader runner`, because `vite.config.ts`
imports `@bc-solutions-coder/env/base-path` as plain Node ESM before any bundle
exists.

## Layout

`src/` uses the same three-zone split as `wallow-web`, enforced by the
`wallow/zone-dag` lint rule rather than by convention: `app/` (host, routes,
router, server-only modules), `features/<name>/` (one directory per screen,
reachable only through its `index.ts` barrel), `shared/` (what more than one
feature needs). Cross-zone imports are spelled `@app/*`, `@features/<name>`,
`@shared/*`, and the alias map lives only in `tsconfig.json` `paths`.

| Path                                       | Role                                                                                                                                                                                                                               |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/app/start.ts`                         | The `createStart()` instance: one global request middleware mints a per-request SDK (`createWallowSdk()`) plus the request's `resolveForkLinks()` pair and hands both to the router. The app's only `process.env` reads live here. |
| `src/app/router.tsx`                       | `createRouter` + `setupRouterSsrQueryIntegration`, wiring the request's SDK and a per-request `QueryClient` into the router context.                                                                                               |
| `src/app/routes/`                          | File-based routes — one screen route per feature, plus the four server routes below.                                                                                                                                               |
| `src/app/routeTree.gen.ts`                 | Generated by the Start Vite plugin as a side effect of `vite dev`/`vite build`. Never hand-edited; there is no `routes:generate` step.                                                                                             |
| `src/app/styles.css`                       | The app's single Tailwind entry, imported for side effects by `app/routes/__root.tsx`.                                                                                                                                             |
| `src/features/<name>/`                     | Sixteen screen verticals. Each has `index.ts` (the barrel), usually `api.ts` (the data seam) and `components/`; several add a `*-result.ts` module holding the narrowing that turns an API response into a screen outcome.         |
| `src/shared/components/`                   | `auth-layout.tsx` (the branded shell and the app's only `<h1>`), `auth-screen.tsx`, `consent-labels.tsx`, `ready-indicator.tsx`.                                                                                                   |
| `src/shared/lib/`                          | `api-passthrough.server.ts`, `log-ingest.server.ts`, `base-path.ts`, `branding.ts`, `fork-links.ts`, `log.ts`, `error-code.ts`, `return-url.ts`.                                                                                   |
| `src/shared/hooks/use-return-url-guard.ts` | The `returnUrl` open-redirect guard the login, signup and MFA screens share.                                                                                                                                                       |
| `Dockerfile`                               | Containerizes the app for the E2E stack; its build context is the **repo root**, and it takes `AUTH_BASE_PATH` as a build `ARG`. Runs `node .output/server/index.mjs`.                                                             |

## Reverse-proxy wiring

TanStack Start's file-based routing supports server routes, so each of these is a
route module exporting `server.handlers` instead of a component. Three of them
delegate to the one bridge in `src/shared/lib/api-passthrough.server.ts`, a thin
wrapper over the SDK's `createApiPassthrough()` preset (built lazily and memoised
at module scope), which forwards method, path, query, body and `Cookie` verbatim
and returns every upstream `Set-Cookie` untouched.

| Route             | File                                | Purpose                                                                                                                                |
| ----------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `/v1/**`          | `src/app/routes/v1/$.ts`            | The Wallow API surface, proxied verbatim.                                                                                              |
| `/connect/**`     | `src/app/routes/connect/$.ts`       | The OpenIddict endpoints (authorize, token, logout, userinfo).                                                                         |
| `/.well-known/**` | `src/app/routes/[.]well-known/$.ts` | OIDC discovery and JWKS. The documents advertise URLs on _this_ origin, so they must resolve here.                                     |
| `POST /logs`      | `src/app/routes/logs.ts`            | Browser-logger ingest. A top-level path, not `/bff/logs` — this app has no BFF.                                                        |
| `GET /health`     | `src/app/routes/health.ts`          | Liveness: `200 ready`, answered without touching the API. Both compose stacks probe it, so the path and body are a container contract. |

The three proxy routes use a single `ANY` handler rather than a method map: the
upstream owns which verbs a path answers, and filtering here would turn an
upstream `405` into a local `404`.

The passthrough hands the runtime's request to the SDK unchanged; the SDK reads the
peer address from `request.ip`, believes an inbound `X-Forwarded-For` only when the
peer is inside `WALLOW_TRUSTED_PROXIES`, and stamps the resolved caller onto the
upstream hop so the API rate-limits per visitor rather than per proxy.

## Base path

This app can be served under a URL prefix, for a path-based ingress that puts
`wallow-web` at the site root. `AUTH_BASE_PATH` is a **build** input, not a
runtime one — Vite bakes it into every emitted asset URL — which is why the
Dockerfile takes it as an `ARG` promoted to `ENV` before `pnpm build`:

```bash
docker build --build-arg AUTH_BASE_PATH=/auth -f apps/wallow-auth/Dockerfile .
```

One value, three shapes, all in `vite.config.ts`: Vite's own `base` (trailing
slash), the Start plugin's `router.basepath` (no trailing slash), and nitro's
`baseURL` — miss the last and the page renders but never hydrates, because the
server keeps serving `.output/public` at the root. The string arithmetic comes
from `@bc-solutions-coder/env/base-path`; only `BASE_PATH` and `toAppHref` are
this app's, in `src/shared/lib/base-path.ts`.

## Environment variables

| Variable                                   | Required | Default         | Purpose                                                                                                                                         |
| ------------------------------------------ | -------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `WALLOW_API_INTERNAL_URL`                  | yes      | —               | Upstream the three proxy routes forward to.                                                                                                     |
| `PORT`                                     | no       | `3002`          | Listen port, read by the host (Vite/Nitro).                                                                                                     |
| `HOST`                                     | no       | —               | Bind address, read by the Nitro server bundle.                                                                                                  |
| `AUTH_BASE_PATH`                           | no       | `""`            | URL prefix this build is served under. **Build-time only.**                                                                                     |
| `WALLOW_WEB_INTERNAL_URL`                  | no       | —               | The app's own self-reachable origin, for SSR fetches (`resolveInternalOrigin`). Not the same variable as `WALLOW_API_INTERNAL_URL`.             |
| `WALLOW_TRUSTED_PROXIES`                   | no       | _(empty)_       | CIDRs whose `X-Forwarded-For` / `X-Forwarded-Proto` are believed. Unset, nothing is trusted: the peer address and the request's own scheme win. |
| `WALLOW_REPOSITORY_URL`, `WALLOW_DOCS_URL` | no       | `branding.json` | The fork's outbound links, stated into the document by `__root.tsx`.                                                                            |
| `OTEL_EXPORTER_OTLP_ENDPOINT`              | no       | —               | Where `/logs` forwards ingested browser records.                                                                                                |

There is no OIDC configuration here. This app issues no tokens and reads no
session; the OIDC contract belongs to `wallow-web`'s BFF and to the API.

## Run locally

```bash
# from the repo root
WALLOW_API_INTERNAL_URL=http://localhost:5001 \
  pnpm --filter @bc-solutions-coder/wallow-auth dev   # http://localhost:3002
```

The screens render without a backend; anything that submits needs the API, which
`pnpm backend` starts on `:5001`.

## E2E

```bash
pnpm --filter ./apps/wallow-auth test:e2e
```

The Playwright config boots `pnpm dev` on 3002 itself (reusing an already-running
server) and defaults `WALLOW_API_INTERNAL_URL` to `http://localhost:5001`. Set
`E2E_BASE_URL` to drive an already-running app and boot no server. For the full
containerized stack — API, seeder, this app on `:5051`, and `wallow-web`'s
cross-app login journey — use `./scripts/e2e.sh` from the repo root.

Suite conventions live in [`e2e/CLAUDE.md`](e2e/CLAUDE.md).
