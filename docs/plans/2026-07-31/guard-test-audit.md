# Guard-test audit — which meta-specs block the build simplification

Audit of the non-behavioural "architecture guard" specs in the pnpm workspace: the tests that
read a config file, a `package.json`, or the filesystem instead of rendering a component or
calling a function.

**Scope surveyed:** 54 guard files. `apps/wallow-auth` 13, `apps/wallow-web` 17,
`packages/sdk` 9, `packages/testing` 4, `packages/ui` 3, `packages/forms` 3,
`packages/query` 2, `packages/styles` 2, plus the two barrel-pin specs
(`packages/ui/src/index.test.ts`, `packages/forms/src/index.test.ts`).

**Classification totals:** A (load-bearing) 20 · B (better as lint/types) 15 ·
C (shape-lock — delete or loosen) 10 · D (redundant) 9.

**Runtime cost is not the problem.** Measured on this machine:

| Suite                                       | Files | Tests | Wall time |
| ------------------------------------------- | ----- | ----- | --------- |
| `wallow-auth` node project (whole)          | 32    | 649   | 0.86 s    |
| — of which the 12 top-level guards          | 12    | **534** | 0.60 s  |
| `wallow-web` top-level guards               | 11    | 188   | 0.50 s    |
| `packages/ui` node project                  | 12    | 131   | 1.45 s    |
| `packages/forms` node project               | 8     | 57    | 0.76 s    |
| `packages/testing` node project             | 5     | 58    | 0.40 s    |
| `packages/sdk` 5 meta-specs                 | 5     | 124   | 0.93 s    |

The guards are **82% of `wallow-auth`'s node test count** (534/649 — they are mostly
`it.each` over feature directories) and cost under a second. The cost is entirely
**maintenance friction**: each one nails a config key in place, and the failure message
points at the config rather than at a behaviour.

## Part 3 — Vacuous / already-false assertions

1. **`expect(deps.typescript).not.toBe("6.0.3")`** — `packages/ui/src/core/package-scaffold.test.ts:117` and `packages/forms/src/core/package-scaffold.test.ts:193`. Both packages declare `"typescript": "catalog:tooling"`, and even `packages/sdk` — the package whose pin this guards against copying — now declares `"catalog:tooling-tsc6"`. **No manifest in the repo can spell `"6.0.3"` any more**, so the assertion can never fail. The invariant it describes is now enforced by the catalog indirection in `pnpm-workspace.yaml`. This is the stale-fact case the brief asked about, in a slightly different form than expected: not a `^5.x` TypeScript pin, but a test written against a literal version string the workspace stopped using when it moved to catalogs (workspace is on TypeScript **7.0.2**, sdk on **6.0.3** via `tooling-tsc6`).

2. **`packages/sdk/src/build-config.test.ts`** — `expect(existsSync(tsupConfigPath)).toBe(false)`, `expect(build).not.toContain("tsup")`, `expect(devDeps).not.toHaveProperty("tsup")`. tsup was removed from this package several releases ago. Three assertions that can only fail if someone deliberately reinstalls tsup. Passing for the wrong reason.

3. **`apps/wallow-web/src/styling.test.ts`** — three specs, each `expect(source).toContain("className")` on one named file. Any React component with a single styled element satisfies it. Near-vacuous by construction; the header admits the bar is "the presence of styling hooks, not any specific class".

4. **`packages/styles/src/branding-ownership.test.ts`** — asserts two docs pages do NOT match a regex naming the deleted Blazor `Wallow.Auth`/`Wallow.Web` apps as canonical branding owner. Those apps are gone from the tree; the docs were rewritten in the same commit. Permanently true.

5. **`packages/ui/src/core/dist-structure.test.ts` skips silently in the default local flow.** All six specs are `skipIf(distIsMissing)`, and `pnpm check` runs `test` **before** `build`. On a fresh clone — or right now, with `packages/ui/dist` renamed to `dist.bak` by concurrent work — all six report green having asserted nothing. Only `.github/workflows/js.yml` (which runs `pnpm --filter './packages/*' build` before `pnpm test`) arms them. Not a fault in the test, but it means the *only* honest build-output guard in the repo is the one most likely to be silently inactive when a developer changes the build.

6. **The inverse case — an unguarded list.** `packages/ui/vitest.config.ts` maintains a 39-entry `baseUiSubpaths` array plus `recipeRuntime`, feeding `optimizeDeps.include` for both its browser projects, and `packages/ui/CLAUDE.md` instructs every component task to append to it. **No test asserts anything about that list.** `packages/forms` has the identical list guarded twice (`browser-deps.test.ts` verifies resolvability, `package-scaffold.test.ts` name-checks entries). So the two packages with the same hand-maintained hack have opposite guard coverage — whoever evaluates deleting the pre-bundle lists can delete `packages/ui`'s freely and will have to edit two tests to delete `packages/forms`'.

7. **`packages/sdk/src/oxfmt-config.test.ts` is currently red** in this working tree — its last spec shells out to `oxfmt --check` across the whole workspace, and unrelated in-flight edits to `packages/ui` stories are unformatted. A `packages/sdk` unit test failing because of an unformatted file in another package is the friction this audit is about.
