# SDK Query Layer + Frontend State Boundary Implementation Plan

**status: active** (2026-07-23) — phases 1–3 landed; Zustand adoption + Query-vs-Zustand docs page remain.

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make TanStack Query the single frontend data store by shipping a centralized query-key factory and curated `queryOptions`/mutation factories from the SDK, adopting them in both apps, introducing Zustand for UI-only state, and documenting the Query-vs-Zustand boundary.

**Architecture:** A new browser-safe `@bc-solutions-coder/sdk/query` subpath owns ALL query keys (one hierarchical factory, zero magic strings) and domain-grouped `queryOptions`/mutation factories that wrap the generated hey-api ops via `unwrap()`. Apps register a lazy one-time client configurator, consume the factories through thin per-feature re-exports, and cache the current user as a query. The dead generated `@tanstack/react-query.gen.ts` layer is removed from codegen. Zustand is added for UI-only global state with the boundary written into CLAUDE.md and a new docs page.

**Tech Stack:** TypeScript, `@tanstack/react-query` v5 (becomes an SDK peerDependency), `@hey-api/openapi-ts` codegen, Vite 8 library mode, TanStack Start/Router, Zustand, vitest (node + browser projects).

**Key facts discovered during investigation (trust these, verified 2026-07-23):**
- `packages/sdk/src/generated/@tanstack/react-query.gen.ts` (3,270 lines) is generated by the `"@tanstack/react-query"` plugin in `packages/sdk/openapi-ts.config.ts:16` but is NOT exported from `packages/sdk/src/generated/index.ts` and has zero importers. It uses structural keys (`[{ _id, baseUrl, ... }]`) incompatible with our hierarchical invalidation, so we remove it rather than adopt it.
- `@tanstack/react-query` is currently a **hard dependency** of the SDK (`packages/sdk/package.json:35`) — must become a peer to avoid dual-instance cache bugs.
- wallow-web already has the target shape hand-rolled in 5 files (`apps/wallow-web/src/features/{organizations,apps,settings,mfa,inquiries}/api.ts`) with 11 inline key literals duplicated across 13 `invalidateQueries` calls. `organizations/api.ts` is the canonical template.
- wallow-auth has NO api.ts layer: 9 inline magic-string keys in components, including a real collision — `["auth", "external-providers"]` (`RegisterForm.tsx:575`) vs `["external-providers"]` (`ExternalProviders.tsx:159`) for the same endpoint.
- wallow-web fetches the current user raw in `beforeLoad` (`routes/dashboard/route.tsx:43`, `routes/index.tsx`), bypassing the cache on every navigation; and it runs TWO QueryClients per request (router context client in `router.tsx:16` vs a `useRef` provider client in `routes/__root.tsx:98`).
- Client configuration is lazy-on-first-use via `createConfiguredOnce` (`packages/sdk/src/facade.ts:51`). Laziness matters: during SSR the context only exists inside the per-request `AsyncLocalStorage` scope (`apps/wallow-web/src/ssr.tsx`). SDK query code must NOT use `import.meta.env.SSR` (not substituted in library builds) — detect SSR via `getSsrRequestContext() !== undefined`.
- No Zustand/Jotai/Redux anywhere in the repo. Almost no cross-component UI state exists today — do NOT build empty stores.

**Conventions that apply to every task:**
- Formatter/linter: `pnpm format` (oxfmt) and `pnpm lint` (oxlint) — never prettier/eslint.
- Component tests run in real Chromium via vitest browser mode; pure-logic tests in the node project. NEVER jsdom (see `.claude/rules/TESTING.md`).
- Build the SDK before typechecking apps: `pnpm --filter @bc-solutions-coder/sdk build`.
- Commit format: conventional commits, lowercase, imperative, <72 chars first line.

**Step 3: Implement** (`bootstrap.ts`):

```ts
/**
 * Lazy one-time client configuration for the SDK query layer.
 *
 * The queryOptions factories in this directory call generated ops on the shared
 * `@hey-api` client, but HOW that client is configured is app-specific
 * (wallow-web: BFF tunnel under `/api` + SSR request context; wallow-auth:
 * same-origin passthrough at `/`). Apps register their configurator once at
 * module scope (side-effect free); the first queryFn to run invokes it. This
 * preserves the `createConfiguredOnce` lazy semantics — nothing touches the
 * shared client until a query actually fires, which is required for SSR where
 * the request context only exists inside the per-request ALS scope.
 */
let configurator: (() => void) | undefined;
let bootstrapped = false;

/** Register the app's one-time client configurator. Re-registering re-arms the guard. */
export function registerQueryBootstrap(configure: () => void): void {
  configurator = configure;
  bootstrapped = false;
}

/** Run the registered configurator if it has not run yet. Safe to call on every queryFn. */
export function ensureQueryBootstrapped(): void {
  if (!bootstrapped) {
    configurator?.();
    bootstrapped = true;
  }
}

/** Test-only: clear registration state. */
export function resetQueryBootstrapForTests(): void {
  configurator = undefined;
  bootstrapped = false;
}
```

**Step 3: Implement** (`keys.ts`):

```ts
/**
 * The single source of every TanStack Query key in the platform.
 *
 * RULES (enforced by convention + review, documented in CLAUDE.md):
 *  - No key literal (`["orgs", ...]`) may appear anywhere outside this file.
 *  - queryOptions factories AND invalidateQueries calls both reference these
 *    builders, so definition and invalidation can never drift.
 *  - Children are built FROM their parent (`[...detail(id), "members"]`) so
 *    invalidating a prefix (`queryKeys.organizations.all`) sweeps the subtree.
 *
 * Root literals preserve wallow-web's shipped keys (`orgs`, `apps`, `settings`,
 * `mfa`, `inquiries`) so adopting the factory does not orphan existing caches.
 */
export const queryKeys = {
  organizations: {
    all: ["orgs"] as const,
    detail: (id: string) => [...queryKeys.organizations.all, id] as const,
    members: (id: string) => [...queryKeys.organizations.detail(id), "members"] as const,
    clients: (id: string) => [...queryKeys.organizations.detail(id), "clients"] as const,
  },
  apps: {
    all: ["apps"] as const,
    detail: (clientId: string) => [...queryKeys.apps.all, clientId] as const,
  },
  settings: {
    all: ["settings"] as const,
    profile: () => [...queryKeys.settings.all, "profile"] as const,
  },
  mfa: {
    all: ["mfa"] as const,
    status: () => [...queryKeys.mfa.all, "status"] as const,
  },
  inquiries: {
    all: ["inquiries"] as const,
    detail: (id: string) => [...queryKeys.inquiries.all, id] as const,
    comments: (id: string) => [...queryKeys.inquiries.detail(id), "comments"] as const,
  },
  auth: {
    all: ["auth"] as const,
    currentUser: () => [...queryKeys.auth.all, "current-user"] as const,
    externalProviders: () => [...queryKeys.auth.all, "external-providers"] as const,
    clientTenant: (clientId: string) => [...queryKeys.auth.all, "client-tenant", clientId] as const,
    consentInfo: (clientId: string) => [...queryKeys.auth.all, "consent", clientId] as const,
    invitation: (token: string) => [...queryKeys.auth.all, "invitation", token] as const,
    verifyEmail: (email: string, token: string) =>
      [...queryKeys.auth.all, "verify-email", email, token] as const,
    redirectValidation: (url: string) =>
      [...queryKeys.auth.all, "redirect-validation", url] as const,
  },
};
```

import { create } from "zustand";

/**
 * Global UI-ONLY state (see docs/development/frontend-state.md).
 *
 * BOUNDARY: nothing fetched from the API may live here. Backend data belongs to
 * TanStack Query (keys from @bc-solutions-coder/sdk/query); this store holds
 * presentation state that must survive across components/routes.

interface UiState {
  isNavOpen: boolean;
  toggleNav: () => void;
  closeNav: () => void;
}

export const useUiStore = create<UiState>()((set) => ({
  isNavOpen: false,
  toggleNav: () => set((state) => ({ isNavOpen: !state.isNavOpen })),

}));
