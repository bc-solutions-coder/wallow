## 3. Rendering model (no portal, singleton state)

| Fact | Source |
| --- | --- |
| `Toaster` renders **inline where it is placed, not through `ReactDOM.createPortal`**. Root is `<section aria-label={customAriaLabel ?? \`${containerAriaLabel} ${hotkeyLabel}\`} tabIndex={-1} aria-live="polite" aria-relevant="additions text" aria-atomic="false" suppressHydrationWarning data-react-aria-top-layer>`; inside it one `<ol data-sonner-toaster data-sonner-theme={actualTheme} data-y-position data-x-position dir=...>` per active position, and **the `<ol>` is not rendered while there are no toasts** (`if (!filteredToasts.length) return null;`). Each toast is an `<li data-sonner-toast data-styled=... data-type=... data-testid={toast.testId} ...>`. | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx |
| Positioning comes from CSS: `[data-sonner-toaster] { position: fixed; width: var(--width); ... }` with `z-index: 999999999` in the base block, and each `[data-sonner-toast] { position: absolute; ... transition: transform 400ms, opacity 400ms, height 400ms, box-shadow 200ms; }`. | https://github.com/emilkowalski/sonner/blob/main/src/styles.css |
| State is a **module-level singleton**: `export const ToastState = new Observer();` with `subscribe`/`publish`. `toast` is `Object.assign(basicToast, { success, info, warning, error, custom, message, promise, dismiss, loading }, { getHistory, getToasts })`. `toast()` can be called from anywhere, including outside React. | https://github.com/emilkowalski/sonner/blob/main/src/state.ts; https://sonner.emilkowal.ski/toast |
| Every mounted `Toaster` subscribes to the same `ToastState` in a `useEffect`. Routing: a `Toaster` with `id` shows only toasts whose `toasterId === id`; a `Toaster` without `id` shows only toasts with **no** `toasterId` (`toasts.filter((toast) => !toast.toasterId)`). **Two id-less Toasters therefore both render every untargeted toast.** | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx (`filteredToasts` memo); https://sonner.emilkowal.ski/toaster ("Multiple toasters") |
| Ids come from a module-level counter (`let toastsCounter = 1`) unless the caller passes `id`; `toast.dismiss()` with no id dismisses all active toasts; `toast.getHistory()` is capped at `MAX_HISTORY_SIZE = 100`. | https://github.com/emilkowalski/sonner/blob/main/src/state.ts |
| `subscribe` **replays active toasts to a new subscriber** ("A toast can be created before the `Toaster` had a chance to subscribe ... Replay whatever is still active"). This is present in the 2.0.8 dist (`this.getActiveToasts().forEach((toast)=>subscriber(toast))`). Issue #723 ("Toast is never shown if called before `Toaster` subscribes") is closed; PR #760 for it is still open, PR #777 ("Fix a batch of reported issues") merged 2026-08-08. The docs page still says a toast on page load must be wrapped in `setTimeout`/`requestAnimationFrame`. | (dist) `dist/index.mjs` ~line 139-147; https://github.com/emilkowalski/sonner/issues/723; https://sonner.emilkowal.ski/toast ("Render toast on page load") |
| Toaster subscriber applies additions via `setTimeout(() => ReactDOM.flushSync(...))` ("Prevent batching, temp solution") and dismissals via `requestAnimationFrame`; `ToastState.dismiss(id)` itself defers the publish to a `requestAnimationFrame`. Removal from the DOM happens `TIME_BEFORE_UNMOUNT = 200` ms after dismissal (exit animation). | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://github.com/emilkowalski/sonner/blob/main/src/state.ts |
| Timers: default `TOAST_LIFETIME = 4000` ms; per-toast `setTimeout` with remaining-time bookkeeping; paused while `expanded \|\| interacting \|\| isDocumentHidden` (hover, swipe, `document.hidden` via `visibilitychange`); `duration: Infinity` skips the timer entirely; `type: 'loading'` and pending promise toasts never auto-close. `onAutoClose` fires on timeout, `onDismiss` on close button / swipe. | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://github.com/emilkowalski/sonner/blob/main/src/hooks.tsx; https://sonner.emilkowal.ski/toast |
| Keyboard: default hotkey `['altKey', 'KeyT']` expands the stack and focuses the list; `Escape` collapses; `visibleToasts` default 3; `gap` default 14; `position` default `bottom-right`; `offset`/`mobileOffset` defaults `24px`/`16px` (mobile breakpoint `max-width: 600px`). | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://github.com/emilkowalski/sonner/blob/main/src/styles.css |
| `prefers-reduced-motion` disables toast transitions/animations in the stylesheet. | https://github.com/emilkowalski/sonner/blob/main/src/styles.css |

## 4. Theming: CSS variables, `classNames`, dark mode

| Fact | Source |
| --- | --- |
| The stylesheet **does not use `prefers-color-scheme` and knows nothing about a `.dark` class**. Palette is keyed on the `data-sonner-theme` attribute of the `<ol>`: `[data-sonner-toaster][data-sonner-theme='light'] { --normal-bg: #fff; --normal-border: var(--gray4); --normal-text: var(--gray12); --success-bg/-border/-text; --info-*; --warning-*; --error-* }` and a `[data-sonner-theme='dark']` block (`--normal-bg: #000`, `--normal-bg-hover`, `--normal-border`, `--normal-border-hover`, ...). `--gray1`..`--gray12`, `--border-radius: 8px` are set on `[data-sonner-toaster]`; `--width`, `--gap`, `--front-toast-height`, `--offset-*`, `--mobile-offset-*` are written as inline styles by the component. | https://github.com/emilkowalski/sonner/blob/main/src/styles.css; https://github.com/emilkowalski/sonner/blob/main/src/index.tsx |
| `theme` prop: `'light' \| 'dark' \| 'system'`, **default `'light'`**. `'system'` reads `window.matchMedia('(prefers-color-scheme: dark)')` (initial state guarded by `typeof window !== 'undefined'`, falling back to `'light'` on the server) and subscribes to `change`. Docs show wiring it from a theme provider (`next-themes` example). | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://sonner.emilkowal.ski/toaster |
| Open bug #782: the `theme` effect adds a `matchMedia` `change` listener on every `theme` change and never removes it (on change or unmount) — "leaks matchMedia change listeners"; fix PR #783 is open. Only relevant when `theme="system"` is used and the prop toggles. | https://github.com/emilkowalski/sonner/issues/782 |
| Default visual styling is gated on `[data-sonner-toast][data-styled='true']` (padding, `background: var(--normal-bg)`, border, `color: var(--normal-text)`, `border-radius`, `width: var(--width)`, buttons, close button, icon). `data-styled` is `!Boolean(toast.jsx \|\| toast.unstyled \|\| unstyled)` — so `toast.custom(...)` toasts and `unstyled: true` toasts get **only** the positional/animation rules. Rich colours are `[data-rich-colors='true']` + `[data-type=...]`. | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://github.com/emilkowalski/sonner/blob/main/src/styles.css |
| `ToastClassnames` keys: `toast, title, description, loader, closeButton, cancelButton, actionButton, success, error, info, warning, loading, default, content, icon`. `toastOptions` keys: `duration, className, descriptionClassName, closeButton, style, unstyled, classNames, cancelButtonStyle, actionButtonStyle, closeButtonAriaLabel` (the `.d.ts` also carries `richColors`, `toasterId`, `testId` on `ToastOptions`/`ExternalToast`). Per-toast `classNames` are concatenated **after** Toaster-level ones (`cn(classNames?.toast, toast?.classNames?.toast, classNames?.[type], toast?.classNames?.[type])`) — plain string join, no tailwind-merge. | https://github.com/emilkowalski/sonner/blob/main/src/types.ts; https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; (dist) `dist/index.d.ts` |
| Official styling guidance: three tiers. (1) `toastOptions.style`/`className` for global overrides; (2) `classNames` per element — the docs state "you will need to use `!important` in order to override the default styles"; (3) `unstyled: true` "removes all styles and apply your own without `!important`", with the Tailwind example `toastOptions={{ unstyled: true, classNames: { toast: 'bg-blue-400', title: ..., description: ..., actionButton: ..., cancelButton: ..., closeButton: ... } }}` and per-type keys (`error`, `success`, `warning`, `info`). The maintainer calls the headless (`toast.custom`) route "the recommended approach as people usually either use the defaults or go fully custom". | https://sonner.emilkowal.ski/styling; https://github.com/emilkowalski/sonner/blob/main/website/src/pages/styling.mdx |
| Why `!important` is needed with Tailwind v4: sonner's CSS is injected as an **unlayered** `<style>` element, while Tailwind v4 "[is] using native cascade layers" (utilities live in `@layer utilities`). MDN: "Styles that are not defined in a layer always override styles declared in named and anonymous layers", regardless of specificity, and `!important` reverses that order. Reported as #591, #602, #619 (all closed; maintainer answer: expected, use `!`/headless/`unstyled`). Tailwind's own escape hatches: the `!` modifier per class (`bg-red-500!`) or `@import "tailwindcss" important;` for all utilities. | (dist) `__insertCSS`; https://tailwindcss.com/docs/upgrade-guide (Adding custom utilities); https://developer.mozilla.org/en-US/docs/Web/CSS/@layer; https://github.com/emilkowalski/sonner/issues/591; https://github.com/emilkowalski/sonner/issues/602; https://github.com/emilkowalski/sonner/issues/619; https://tailwindcss.com/docs/styling-with-utility-classes#managing-style-conflicts |
| Icons are replaceable globally (`icons={{ success, info, warning, error, loading }}`) or per toast (`icon`, `null` hides). | https://sonner.emilkowal.ski/styling |

## 5. `<Toaster>` and SSR (TanStack Start)

| Fact | Source |
| --- | --- |
| Docs: `<Toaster />` "can be placed anywhere, even in server components such as `layout.tsx`". The file is `'use client'`. | https://sonner.emilkowal.ski/getting-started; (dist) `dist/index.mjs` line 1 |
| Server-safe code paths in `Toaster`: `getDocumentDirection()` returns `'ltr'` when `typeof document === 'undefined'`; the `theme` initial state falls back to `'light'` when `typeof window === 'undefined'`; `useIsDocumentHidden` (reads `document.hidden` in a `useState` initializer) lives in `Toast`, which is only rendered once toasts exist. Server markup is therefore the empty `<section aria-live ... suppressHydrationWarning>` with no `<ol>`. | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://github.com/emilkowalski/sonner/blob/main/src/hooks.tsx |
| Known SSR pitfalls: #528 — `<Toaster />` placed as a child of `<html>` gives "In HTML, `<section>` cannot be a child of `<html>`" hydration error; maintainer (2026-08-05): "`<Toaster />` has to be inside `<body>`". #695 (hydration mismatch, closed "not planned" by the reporter who stopped using sonner; a commenter noted it "seems the component wasn't rendered server-side"). #608 (Astro first render shows toasts as block elements) — maintainer: import `sonner/dist/styles.css` manually; docs "Other > Astro": "If you use Astro with view transitions, or run into any other Sonner issues with Astro, please import Sonner's styles into a layout file." | https://github.com/emilkowalski/sonner/issues/528; https://github.com/emilkowalski/sonner/issues/695; https://github.com/emilkowalski/sonner/issues/608; https://sonner.emilkowal.ski/other |
| Because `__insertCSS` is a no-op on the server, **SSR HTML contains none of sonner's CSS**; it is added to `<head>` when the client bundle evaluates. No toast can be visible before hydration anyway (toasts are client state), so this affects only stylesheet ordering, not first paint. | (dist) `dist/index.mjs` lines 1-10 |
| TanStack Router/Start client-only tools, should a client-only mount be wanted: `<ClientOnly fallback={...}>` from `@tanstack/react-router` ("render a component only in the client, without breaking the server-side rendering due to hydration errors"; renders `fallback` during SSR and first client render), `useHydrated()` (false during SSR and first client render, true after hydration), and `createClientOnlyFn` from `@tanstack/react-start` (throws on the server). | https://tanstack.com/router/latest/docs/api/router/clientOnlyComponent; https://tanstack.com/start/latest/docs/framework/react/guide/execution-model#client-only-execution |

## 6. `toast.error` + description/action vs `toast.custom` (headless)

| Fact | Source |
| --- | --- |
| `toast.error(message, data?)` creates `type: 'error'`. `ExternalToast` fields include `description` (`ReactNode` or `() => ReactNode`), `action` and `cancel` (`Action \| React.ReactNode`), `duration`, `dismissible`, `onDismiss`, `onAutoClose`, `icon`, `unstyled`, `className`, `classNames`, `style`, `position`, `closeButton`, `actionButtonStyle`, `cancelButtonStyle`, `id`, `toasterId`, `testId`, `richColors`. `Action = { label: ReactNode; onClick: (event: React.MouseEvent<HTMLButtonElement>) => void; actionButtonStyle?: CSSProperties }`. | https://github.com/emilkowalski/sonner/blob/main/src/types.ts; (dist) `dist/index.d.ts` |
| Action button: renders `<button data-button data-action>` inside the toast; clicking calls `onClick(event)` then `deleteToast()` **unless `event.defaultPrevented`** — so a "retry" or "copy trace id" action can keep the toast open with `event.preventDefault()`. Cancel button (`data-cancel`) always closes (no `preventDefault` check) and is skipped when `dismissible === false`. Either slot also accepts arbitrary JSX (`action: <Button .../>`), in which case sonner renders it verbatim with no close-on-click behaviour. Only one `action` and one `cancel` slot exist. | https://github.com/emilkowalski/sonner/blob/main/src/index.tsx (action/cancel render block); https://sonner.emilkowal.ski/toast ("Action", "Cancel") |
| `title` and `description` may be functions returning JSX ("Rendering custom elements"). `toast(<div/>)` (JSX as first argument) keeps default styling; `toast.custom((t) => <JSX/>, data?)` is the headless form: it receives the id, sets `jsx: jsx(id)`, `type: undefined`, and the `<li>` gets `data-styled="false"`. The close button is not rendered for `jsx` toasts (`closeButton && !toast.jsx`), and the built-in title/description/action/cancel markup is bypassed. | https://github.com/emilkowalski/sonner/blob/main/src/state.ts; https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://sonner.emilkowal.ski/toast ("Custom", "Headless") |
| Headless toasts still get sonner's `<li>` wrapper with `tabIndex={0}`, positioning, swipe, timers, and the `aria-live` region — but since v1.6 the wrapper intentionally no longer adds `role`/`aria` attributes for `toast.custom` (#519 closed as intentional; maintainer "open to updating it"). Known headless issues: #652 (`toast.loading` -> `toast.custom` chain never dismissed; closed via PR #777), #748 (open: custom toast height bleeds through shorter front toast in stacked view), #679 (undefined `id` to `toast.custom` gave inconsistent id; closed). | https://github.com/emilkowalski/sonner/issues/519; https://github.com/emilkowalski/sonner/issues/652; https://github.com/emilkowalski/sonner/issues?q=is%3Aissue+%22toast.custom%22 |
| `toast.promise(promise, { loading, success, error, description, finally })` returns the id with an `.unwrap()`; an `error`/`success` value may be a function of the result or an object (`PromiseIExtendedResult`) carrying `message` plus other toast options; HTTP `Response` with `!ok` is treated as an error. `useSonner()` returns `{ toasts }` for fully custom rendering. | https://github.com/emilkowalski/sonner/blob/main/src/state.ts; https://github.com/emilkowalski/sonner/blob/main/src/index.tsx |
| Updating: calling any `toast.*` with an existing `id` updates that toast in place (`create` merges when `alreadyExists`). | https://github.com/emilkowalski/sonner/blob/main/src/state.ts; https://sonner.emilkowal.ski/toast ("Updating toasts") |

## 8. Two React roots, Storybook, other pitfalls

| Fact | Source |
| --- | --- |
| Two roots / two `Toaster`s: because `ToastState` is a module singleton and every `Toaster` subscribes to it, two id-less `Toaster`s in the same JS module graph each render every untargeted toast (duplicate toasts). This is exactly what #618 reported for a root + drawer pair ("there will be two duplicate toasts") and what the `id` / `toasterId` pairing (2.0.7, "Multiple `<Toaster />` components") exists to solve. Two separate module instances (e.g. two bundles) would each have their own `ToastState` and not share toasts. | https://github.com/emilkowalski/sonner/blob/main/src/state.ts; https://github.com/emilkowalski/sonner/blob/main/src/index.tsx; https://github.com/emilkowalski/sonner/issues/618; https://github.com/emilkowalski/sonner/releases |
| Storybook: the issue tracker has **no Storybook-specific reports** (query `is:issue storybook` returns only #306, an ARIA bug). The Storybook Vitest addon runs stories "in browser mode, using Playwright's Chromium browser"; because `ToastState`, `toastsCounter`, and the `__insertCSS` `<style>` element are module-level, they persist across stories rendered in the same page — undismissed toasts from one story remain in `ToastState` and will be replayed to the next story's `Toaster` on subscribe (see the replay fact in section 3). `toast.dismiss()` clears all active toasts. | https://github.com/emilkowalski/sonner/issues?q=is%3Aissue+storybook; https://github.com/storybookjs/storybook/blob/next/docs/writing-tests/integrations/vitest-addon.mdx (How it works); https://github.com/emilkowalski/sonner/blob/main/src/state.ts |
| StrictMode: `create()` cancels a pending (rAF-deferred) dismissal of the same id so React's double effect in StrictMode does not remove a toast that was just created. | https://github.com/emilkowalski/sonner/blob/main/src/state.ts |
